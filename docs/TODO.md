# 项目待办

当前设计见 [图片索引设计](index-design.md)；[已批准实施计划](ingestion-index-management-plan.md) 原文保留，其中阶段状态属于计划记录，不作为实时进度。以下区分当前代码/接口范围与尚未进行的真实验收，不发布历史私人图库路径或把旧图库计数当成本轮结果。

## 当前三能力范围

| 能力 | 当前职责 | 边界 |
| --- | --- | --- |
| ingestion | 增量导入、基础元数据、原图路径、等比例 SQLite JPEG 缩略图；保留 `--album-name` | 不调用模型、不自动 index、不删除原图 |
| index | 显式 setup/configure、图片 embedding 的 plan/execute/status/job/resume；历史配置与结果保留 | 不通过描述中转，不自动改默认、不做技术参数 |
| management | 相册/照片查看，Unicode 名称/文件名查找，中英文语义搜图，只读快照 | 不新增相册写入或选片控件，不自动补索引或切换搜索模式 |

初始模型固定为 `google/siglip2-base-patch16-224`，revision `75de2d55ec2d0b4efc50b3e9ad70dba96a7b2fa2`，Transformers + PyTorch CPU FP32。官方 224×224 方形缩放只用于推理，已保存缩略图保持比例；不自行裁剪/填边。模型只在 `index setup` 显式下载，初次 setup 也不设置默认，需另行 `index configure` 或显式指定 profile。

schema v7 只创建 13 张在用表，保留照片、相册、扫描、缩略图以及 `image_index_profiles/results/runs/items/claims/settings` 六张图片索引表。v1-v6 库先一致性备份，再删除 9 张废弃 analysis/旧文本向量表；现有图片索引及其历史不重算、不改变。空的 `image_index_claims` 仍用于并发保护。index 读取保存预览；ingestion error 需修复后再处理。

旧 OpenAI/Codex 分析链路、命令、状态/报告和相关配置已删除；共用指纹算法已独立，既有 profile ID 不变。废弃表从活动数据库移除，历史数据仅留在迁移前备份，不在后续执行中重新创建。相册写接口及 `search-add` 仍兼容保留。旧验收记录不能证明其他图库或模型的效果。

## 必须后续完成

- [ ] **单独授权后验证下载与真实离线推理。** 代码批准不包含模型下载、照片试跑或正式库迁移授权。先确认兼容解释器/可选依赖，再下载固定清单，实测中断恢复、损坏文件处理和真正断网加载。普通计划/索引/搜索不得自动联网安装或回退云端。
- [ ] **真实模型质量与资源验收。** 先用非敏感测试图，再使用用户明确指定的代表性照片；人工标注中英文配对查询，覆盖主体/场景/色彩/构图/组合、精确条件和无匹配情况。报告 top-K、Recall@K、语言差异及失败样例；实测模型加载、逐图编码、文字编码、排序、内存。当前不承诺速度、节省量或检索质量。
- [ ] **其他图库迁移与恢复演练，另行授权。** 先保留一致性备份，再检查完整性、外键、保留表的逐行内容/摘要、缩略图和图片向量 BLOB；废弃表数据在旧库备份中检查。验证旧代码加备份的回滚路径，不把当前测试图库结果泛化到其他数据库。
- [ ] **NaFlex 新 profile。** 明确输入分辨率/patch 或 token 预算、处理器和运行时身份；与当前 224 模型比较中英文检索质量、比例相关失败、内存和耗时。保留现有索引，不原地替换向量；仅在明确请求后切换默认。
- [ ] **技术参数独立能力扩展。** 先定义字段、单位、适用输入范围（缩略图或原图）、算法/模型来源及版本。与 embedding 分开状态、任务、失效规则和重跑；未实现时不写空结果伪装已完成，也不把模型主观描述当测量值。
- [ ] **ONNX / 量化独立评估。** 验证目标平台运行时和依赖兼容性，测量内存/延迟，检查向量数值与归一化、排序变化和真实检索质量。使用新 profile/runtime 身份；不与 FP32 结果原地混用，不因同维度跨配置补齐。
